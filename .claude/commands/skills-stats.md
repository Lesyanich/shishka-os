Покажи **статистику Skill Advisor** — какие 💡-подсказки реально пригодились, а какие шумят.

## Что делать

1. Запусти `sh scripts/skill-advisor-stats.sh`.
2. **Покажи stdout как есть** — таблица (tool · suggested · accepted · rate) + секция Tuning hints.
3. Разбери Tuning hints:
   - **⚠ noisy** (часто предлагается, редко используется) — предложи сузить/убрать шумные триггер-слова этого инструмента в `ADVISOR-MAP` (`docs/operations/skill-advisor.md`). Покажи конкретный diff и спроси подтверждение.
   - **✅ strong** (высокий acceptance) — можно добавить ещё триггеров/синонимов, чтобы ловил больше формулировок.
4. Любые правки `ADVISOR-MAP` — только с подтверждением CEO (RULE-SKILL-ADVISOR). После правки прогони `/skills-audit`, чтобы реестр остался консистентным.

## Как считается «accepted»

Подсказка засчитана принятой, если предложенный инструмент был **реально вызван** (skill / slash-команда / MCP) в той же сессии в момент ≥ времени подсказки. Сигнал авто-детектируется двумя хуками (suggest-лог в `scripts/skill-advisor.sh`, use-лог в `scripts/skill-advisor-usage.sh`) → общий `.claude/.skill-advisor-log.jsonl`.

## Ограничения (v1)

- Лог **локальный** (per-machine, gitignored) — статистика по этой машине. Результат обучения (подкрученные keywords) синхронизируется через git/реестр.
- Матчинг tool↔usage — токенный (нестрогий); редкие ложные срабатывания возможны.
- Нужно ≥5 подсказок на инструмент, чтобы выводы были осмысленными.
