## Goal
On https://shishka-os.vercel.app/hr/payroll, each employee row expands to a full **payslip** (расчётный листок) that the CEO can **download as PDF**. Payslips are generated monthly from the same data the payroll table already uses.

- Route `/hr/payroll` → `apps/admin-panel/src/pages/hr/PayrollPage.tsx`. It is **period-based**, not live-from-staff: lists `payroll_periods`, each expands to `payroll_lines`.
- Hook `apps/admin-panel/src/hooks/use-payroll.ts` → `PayrollPeriod` + `PayrollLine` interfaces. Actions: `createPeriod`, `calculatePayroll` (RPC `fn_calculate_payroll`), `approvePayroll` (RPC `fn_approve_payroll` → creates expense_ledger entries), `getLines`.
- DB: migration `supabase/migrations/0098_hr_payroll_attendance.sql` defines `payroll_periods`, `payroll_lines`, `attendance_log`, and the RPCs.
- `PayrollLine` already has: days_worked, days_absent, days_leave_paid, base_salary, overtime_pay, absence_deduction, sso_employee, sso_employer, withholding_tax, other_deductions, net_pay, expense_ledger_id.
- Calc day basis = real calendar days via `DATE_PART('days', period_end)` in the RPC — **NOT** hardcoded 30. (My earlier draft wrongly claimed a 30-day bug — retracted.)
- Stack: Vite + React 19 + Tailwind v4 + lucide-react. **PDF lib: none installed** (only `xlsx` present).

## What to build

### 1. Payslip data model (extend PayrollRow → PayslipData)
Already in `PayrollRow`: base_salary, days_worked, days_in_month, overtime_hours, overtime_pay, gross_salary, ssf_employee, advances, total_deductions, net_salary. Add from `staff`: name, name_th, role, nationality, hire_date, employment_type, sso_number, monthly_salary. Add period: month, year, period_start, period_end.

### 2. Calculation contract (MUST match finance WF-7 — do not invent)
```
calendar_days   = days in selected month (28-31), NOT hardcoded 30
daily_rate      = monthly_salary / calendar_days
hourly_rate     = monthly_salary / (calendar_days * 8)
# new hire / leaver pro-rate:
employed_days   = overlap(period, [hire_date, fire_date]) in days
base (full)     = monthly_salary - unpaid_days * daily_rate
base (partial)  = monthly_salary * employed_days / calendar_days   # if hired/fired mid-period
overtime_pay    = overtime_hours * hourly_rate * 1.5
gross           = base + overtime_pay + holiday_pay
ssf_employee    = sso_number ? min(gross * 0.05, 875) : 0          # 2026 cap 875
net             = gross - ssf_employee - advances - other_deductions
```
The RPC already uses real calendar days (`DATE_PART('days', period_end)`). The payslip UI should READ from `payroll_lines` (the calculated snapshot), not recompute — so payslip always matches what was approved/paid.

### 3. Payslip UI (expandable row OR modal)
Click employee row → payslip panel. Layout = formal расчётный листок:
- **Header:** "Shishka Healthy Food Company Limited" + "Payslip / Расчётный листок" + period (e.g. "May 2026") + generation date.
- **Employee block:** name (+ name_th), role, nationality, hire date, employment type, SSO number (or "not enrolled").
- **Earnings table:** Base salary, Overtime (hrs × rate × 1.5), Holiday pay → Gross.
- **Deductions table:** SSF (5%, cap 875), Advances, Other → Total deductions.
- **Attendance block:** calendar days, days worked, unpaid absences, paid leave, OT hours.
- **NET PAY** — large, bold.
- **Footer:** employer signature line + employee signature line + "Generated by Shishka OS".
- Show the **formula breakdown** (like the .md payslips) so numbers are auditable.

### 4. PDF download
- Add a "Download PDF" button per payslip + optional "Download all (zip)".
- **Recommended lib:** `@react-pdf/renderer` (clean declarative PDF, no canvas hacks) OR `jspdf` + `jspdf-autotable` (lighter, table-friendly). Pick one — finance suggests `@react-pdf/renderer` for a real document look. AVOID html2canvas (blurry, font issues).
- Filename: `payslip_{staffName}_{YYYY-MM}.pdf`.
- A4, THB formatting `฿ X,XXX`, English (i18n-ready strings per project constraint).

### 5. Monthly generation — snapshot ALREADY exists
- The system already snapshots: CEO creates a period → Calculate (writes `payroll_lines`) → Approve (creates expense_ledger). Payslip should render from the existing `payroll_lines` row for that period+staff. This is the audit-correct source (immutable once approved). **No new table needed, no live recompute.**
- Payslip = one `payroll_lines` row + the matching `staff` row (for name/role/hire_date/sso_number) + the `payroll_periods` row (for dates).
