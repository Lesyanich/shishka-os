06Заказ ↔ Чек ↔ Расход — одна цепочка

После доставки чек прикрепляется прямо к заказу — кнопкой на карточке. Дальше работает наш обычный конвейер чеков (receipt inbox → распознавание finance-агентом), но результат возвращается в заказ: сверка предзаполняется фактическими цифрами из чека. Расход создаётся один раз — двойного учёта нет.

  • Без двойного учёта: расход создаёт только Reconcile заказа; чек, привязанный к заказу, автоматически закрывается в inbox с тем же expense_id и не обрабатывается как отдельный расход.
  • Перекрёстные ссылки: в разделе чеков видно «этот чек → PO-0011», в заказе — миниатюра чека и итоговый расход. Покупки без заказа (стихийные) идут по старому пути через inbox, как раньше.
07Заявки отделов → заказ → локации

Каждый отдел подаёт свои потребности со своей станции («кухне 2 кг курицы», «бару апельсины») — заявки падают в очередь, из неё собирается заказ, и заявитель видит статус своей позиции до самой доставки. При сборке заказа позиции распределяются по локациям: можно разбить на два заказа (Makro возит и туда и туда) или оставить одну доставку и перебросить самим (порог минимального заказа у поставщика учитывается автоматически).

  • Заявки — расширение существующей вкладки Requests: любой повар подаёт потребность со своей станции (с телефона), у каждой строки виден путь: заявка → в заказе → едет → доставлено. Ничего не теряется в чатах.
  • Локация у каждой строки заказа: подтягивается из заявки автоматически. Один поставщик в обе точки = два заказа; одна доставка с порогом = один заказ с пометками «→ L1 / → L2» и внутренней переброской. Порог из карточки поставщика (min_order) подсказывает сам.
  • Роли: галочка «Ordering» на сотруднике в User Management — новый шеф с галочкой сам собирает и отправляет заказы (без доступа к остальной админке task_manager-уровня). Заявки — доступны всем поварам без галочки.
  • Стоки: каждая принятая строка приходит с меткой станции — приёмка автоматически кормит учёт остатков по локациям. Сам раздел стоков проектирует другая сессия (connected-stock) — сцепка заложена здесь.
Что уже готово и не переделывается: статусная модель заказа в БД, создание заказа, приёмка со сверкой (/receive: принято/брак/недовоз по строкам), Reconcile → расход + склад, Price Book со сравнением цен. Мы достраиваем: редактирование заказа, доску с автором и «NEW», хаб ссылок поставщика, сборку из каталога — и прогоняем весь цикл E2E-тестом под ролью Минт.
